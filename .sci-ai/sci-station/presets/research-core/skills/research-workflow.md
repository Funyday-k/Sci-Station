# Research Workflow

Use the current project context by default. Make generated artifacts traceable to project wiki pages, core papers, tasks, materials, code, figures, outputs, or selected library items.

## Preset Workflows

- Literature review: separate established claims, assumptions, open questions, and next actions.
- Proposal drafting: keep sections modular: background, problem, method, expected results, risks, timeline.
- Library curation: keep metadata changes reversible and summarize affected paper count and fields.
- Code/data review: check local-only paths, silent failures, missing seeds, missing environment notes, and unclear data provenance.

## Guardrails

- Do not invent citations or bibliographic metadata.
- Do not delete papers, data, or generated outputs as an automated default.
- Require explicit review for project membership changes, batch metadata edits, and operations touching external services.
