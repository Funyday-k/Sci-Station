Sci-Station 本机接口

下载契约可查询科研项目、工作区模块、共享文献、AI 实验室和圆桌的请求字段、响应结构和状态码。

下载 OpenAPI 3.1 ↓

接口默认地址 http://127.0.0.1:18765；若更换启动端口，请同步修改导入工具的 server 变量。

请求约定

写入请求须带 X-Roundtable: 1。JSON 请求使用 Content-Type: application/json，通常传单个对象。文件上传使用 multipart/form-data。科研接口允许无请求体的 DELETE 省略 Content-Type；删除 AI 实验室个人模板须用 JSON 传 revision。

Host 必须是当前服务端口的 127.0.0.1 或 localhost。若有 Origin，须精确匹配 http:// 加当前 Host；Sec-Fetch-Site: cross-site 会被拒绝。无 Origin 的本机程序客户端可调用。

X-Roundtable 用于防跨站请求。本接口供本机客户端使用。早期设置中的 magpie_port 为本机 Magpie 默认端口及兼容诊断端口。已注册 Agent 使用 Magpie 写入的连接配置。

Studio 解析单个 JSON，常规请求上限 4 MiB；诊断请求上限 64 KiB。常规对象拒绝未知字段，设置补丁按已知键校验。Studio 新会话的 topic 与补充指令 note 最多 12,000 个 Unicode codepoints。JSON 错误形如 {"error":"说明"}。响应不缓存。

创建项目圆桌并运行议程

  1. 选择项目和成员。向 POST /api/studio/sessions 传议题、项目绝对路径与 members。成员须来自 GET /api/studio/models，按顺序分配 member-1 等席位 ID，第一位为首席。应用读取模型目录校验并保存会话。使用成员模式时，会话保存后异步请求首席拟议程，标题命名单独请求。
  2. 设置讨论方式。传可选的 preset。四种现有预设都可附 continuous 配置，不会新增一种预设。成员模式创建时可先保存配置，但不会自动运行首轮。已有调用方可用 agenda 提交既定事项，可用标题字符串或带 title、kind 的对象，最多 24 项。桌面新建时由首席按议题拟议程。
  3. 启动讨论。向 …/{id}/run 传当前 rounds.length 为 expected_round。可附 agenda_version、note、target、preset、phase。传 continuous 对象明确启动一批持续推进；省略或传 null 始终只运行手动单轮。轮询 GET …/{id} 观察进度，202 表示已接受。

… 在本节均为 /api/studio/sessions。会话状态为 ready、running、partial、closed；每席及子代理为 pending、running、done、error。partial 可能来自失败或停止，检查对应错误，不推定所有工作均已撤回。

会话的可选 continuous 状态含配置、configured / active / paused / completed 状态、当前 round / review / summary 阶段、批次起始轮、已复核轮、目标席位、原因、下一步和依据。目标被确认完成后，批次变为 completed，会话仍保持打开；需要另行调用报告接口结束会议。

GET …/{id} 支持条件轮询：将响应的 ETag 原样放入下一次请求的 If-None-Match，会话未变化时返回 304 且无响应体，变化时返回完整会话和新的 ETag。

POST …/{id}/report 的 finish 是显式结束会议并进入报告阶段的操作；持续推进判定完成不会自动关闭会议。retry 需要指出失败报告的 attempt。报告状态依次可能为 drafting、reviewing、revising、ready 或 failed。报告含 Markdown、错误说明、复核模式（peer、same_model、self）、作者与复核席位和型号、复核意见、纳入的公开发言数及草稿标记。可选 coverage 在材料被节选时说明覆盖范围；报告阶段恢复用的 draft_text 是中间材料，不是最终报告，界面以 markdown 展示。报告材料序列化预算为 64 KiB，超长发言按首尾摘录并保留来源编号；无法为所有公开发言保留可核对原文时报告会失败并保留材料草稿。生成中返回 202；已结束操作可幂等返回 200。只有报告可用后 GET …/{id}/report.md 才能下载。

POST …/{id}/title 是显式命名操作。没有标题时使用本场首席型号请求短标题，成功后保存并复用；已有标题直接返回，不再调用模型。原始 topic 不变，完整会话与摘要可带可选的 title。它不启动工作轮次，不读取项目文件；命名最多 30 秒，并受单次调用超时与请求取消限制。GET 会话、GET 列表和轮询不生成标题。

命名请求必须是空对象 {}，不能省略请求体、传 null 或增加字段。请求格式错误返回 400，来源／标记不符 403，会话不存在 404，非 POST 返回 405，应用关闭冲突 409，首席模型未成功返回标题 502。失败后可显式重试，不以本地拼接议题代替真实命名。

查看和更换席位模型

GET /api/studio/sessions/{id}/members 按原顺序返回 {"members":[…]}。每项包含席位 id、模型 model、名称 label、来源 source 和思考强度 effort。version 省略时按 0。旧式固定席位会话也可通过此接口读取实际配置，单席覆盖保存在完整会话的 seat_overrides。读取不启动模型调用。

POST /api/studio/sessions/{id}/members
Content-Type: application/json
X-Roundtable: 1

{"seat_id":"member-1","model":"provider/model","effort":"auto","expected_version":0}

请使用 GET /api/studio/models 返回的完整模型 ID 和对应思考强度。expected_version 取该席位的当前版本。保存成功返回完整会话，相同的已保存配置可幂等重试。无效的席位、型号或强度返回 400，模型目录读取失败返回 502。

只有轮次之间且会议仍可编辑时才能保存。正在起草、运行或进入报告阶段时，以及该席位版本已更新时，返回 409 与 {"error":"…","session":{…}}，其中包含当前会话。

席位编号、顺序和对应的公开记录保持连续。更换型号会增加席位的 model_epoch，保留 previous_model 和已存在的轮数 switched_after_round。新型号通过独立的网关对话接续，并从会话快照读取公开历史与当前议题板。同一型号只调整思考强度时沿用网关对话。

历史发言使用各轮 turns[].model、effort、model_label 和 model_source 显示当时的配置。标题和议题板模块使用保存的 source_seat、source_round、model、model_label 和 model_source 归因。议程的原始模型信息可见于 source_model、source_model_label 和 source_model_source。持续推进检查点的 items[].model 标记被引用的公开发言模型。旧档中部分归因字段可省略。

本机项目与规则导入

GET /api/studio/projects 返回当前科研工作区的活动项目，每项包含 id、path、name 和 rule_count。向同一接口 POST {"path":"/absolute/project"} 可登记选定目录，成功时返回活动项目列表。

GET /api/studio/projects/import 返回可选目录及其来源 candidates，以及旧版路径登记的只读摘要 legacy。历史摘要含 path、name 和 rule_count。

向 POST /api/studio/projects/import 提交 {"action":"preview","paths":["/absolute/project"]}。预览返回 projects，每项含 path、name、rules 和因限额省略的规则数量 omitted；已有项目还返回 id。提交 action:"apply" 及 selections，每项用 path 指定目录、用 rules 提交选中规则的相对 path 和 digest。已有项目可同时带入预览中的 id。文件变化时返回 409，重新预览后再提交。

GET /api/studio/projects/rules?id=… 读取保存的规则副本。POST /api/studio/projects/rules 提交 {"id":"…","rule":{"path":"AGENTS.md","digest":"…"}} 可停用指定版本。重复停用幂等，规则已有新版本时返回 409。兼容请求可以使用绝对项目 path，此时路径须唯一匹配当前已授权的活动项目；若同时提交 id，两者须对应同一项目。单次最多预览或导入 12 个项目，每个项目可保存至多 24 条规则和 64 KiB 规则上下文。

使用 GET /api/studio/projects/rules?legacy=1&path=… 按历史摘要的原始绝对路径只读查看旧规则。此请求只使用路径，适用于旧记录查阅和恢复。

POST /api/studio/open-rules 接受 {}，生成只读的 discussion-rules.md，并用桌面默认文本编辑器打开。成功返回 {"path":"…"}；打开失败时响应可同时含 path 和 error。

讨论方式与阶段

创建时提交 project_id，取自当前科研项目；全局圆桌提交 scope:"global" 并省略项目字段。全局圆桌没有项目文件权限。已保存的项目标识用于后续打开会话和接收论文摘录。项目目录授权失效后，仍可读取已保存的会议记录。

当前四个预设 work、review、prioritize、forum 都能使用同一持续推进配置；持续推进不是第五种预设。每轮按所选预设继续其阶段和读写约束。

GET /api/studio/discussion-presets 返回 {"presets":[{"id":"…","label":"…","phases":[{"id":"…","label":"…","instructions":"…"}]}]}。instructions 是实际使用的共享规则、场景与阶段指令，来自项目的 internal/deliberation/policy.go；读取不启动模型、不保存设置。

POST /api/studio/sessions/{id}/run
Content-Type: application/json
X-Roundtable: 1

{"expected_round":1,"agenda_version":2,"continuous":{"goal":"完成部署说明","criteria":"包含部署和回滚步骤"}}

指定 target 时可传本场席位 ID、唯一对应的模型 ID 或显示名称；在持续推进批次中，该席位固定执行自动轮。省略 target 时由预设确定参与席位（例如 synthesis 仅运行首席）。停止用现有 POST …/{id}/cancel；它会暂停批次并保留检查点。之后必须再次显式提交 continuous 对象启动新一批，不能只靠轮询或恢复接口自动续跑。

continuous 可包含 goal、criteria、max_rounds、summary_every。goal 省略或为空时使用原议题；两个文本各限 12,000 个 Unicode codepoints。轮数默认 12，范围 1–60；摘要间隔默认 4，范围 2–12。每轮全部席位完成后进行证据复核；有席位失败时先暂停，不作完成判定。达到摘要间隔时生成滚动检查点。摘要请求上限 64 KiB、输出上限 32 KiB，每份最多 24 项；每项正文最多 600 个码点、引文最多 240 个码点。达到 max_rounds、实际阻塞、席位失败、连续两轮无可核实进展或用户取消会暂停批次。continuous.manual:true 表示最近一次显式启动是手动单轮，此时原持续推进配置和检查点仍保留。

每次自动复核最多纳入 12 条公开发言并使用有界文件与变更摘录；复核输入上限 36,000 个 Unicode codepoints，输出上限 16 KiB、最多 12 条原文依据。出处无法完整覆盖时会暂停持续推进而不凭不完整材料判定完成。重新提交相同 goal 与 criteria 会沿用上次检查点；更换目标或验收条件会建立新的检查点链。应用退出也会暂停当前批次，已保存工作不自动重放。

省略预设时按会话和当前议程确定：实施用 work，旧模板阶段用议程项的预设和阶段，其他讨论沿用会话预设，项目协作会话里的讨论事项默认用 review。没有预设或议程的旧记录按 work/work。所有讨论轮次仅读取项目文件。旧调用可以继续发送 allow_edits，新轮次的 settings.allow_edits 始终为 false。历史轮次保留原权限与变更记录。每轮快照还可含 project_rules（路径与摘要），标识启动时读取的规则版本；正文只作为本轮上下文。无效组合返回 400；轮号或议程版本过期返回 409。

持续推进状态可含 checkpoint，由 through_round 与有依据的 items 构成。每项保存简明内容、原轮次、席位和逐字引文；无法生成新摘要时保留上一份有效检查点。每个自动轮在 rounds[] 中标记 auto:true，到检查点后另存该轮 checkpoint，便于按历史轮次回看。自动轮由复核决定继续阶段和下一步，不重放用户指令；明确 target 时该席位在自动批次中保持固定，否则沿用预设的席位规则。

议程从完整会话中读取。agenda 中的事项状态为 pending 或 done，类型为 discussion 或 implementation，来源为 host、template、chair 或 discussion。收束产生的待办记录为 synthesis。会话还可含 active_agenda_id，有效焦点保存为轮次的 agenda_item_id。

POST …/{id}/agenda 需提交 expected_version，取自会话的 agenda_version。操作 add 带 title 与可选 kind；select、complete、reopen 带 item_id。对议程项的 candidates，可用 adopt_candidate 或 dismiss_candidate，并同时传 item_id 与候选 candidate_id。采用会将候选标题和类型作为新修订，忽略只移除该候选；候选已变化或议程版本过期返回 409。select 可附 kind，将未完成事项改为讨论或实施。普通操作成功返回完整会话。首席草拟状态见 agenda_draft_status。失败时可提交 action:"draft" 重试。该操作返回 202 与会话快照，已经在草拟或完成时直接返回状态。普通更新遇到正在草拟、正在运行或版本不符时返回 409。

每轮中，各席的最终公开发言可附 points 与 positions：points 逐字记录该发言明确提出的新观点；positions 以可见的 point_id 记录本人立场 support、oppose、qualified 或 undecided，并附同一发言中的逐字理由。沉默不算赞成，模型不能替其他席表态。完整会话保存这些字段，报告据此呈现立场变化和少数意见。

只读讨论隔离同轮席位输出，仍共享原议题和此前发言。收束默认仅首席执行，可明确点名另一席。各席在公开发言中可附 agenda_updates，用 op:"add" 增加事项，或用 op:"revise" 和 item_id 修订开放事项，并提交 title 和 reason。每席最多保存三项有效提议。轮次成功结束后保存有效提案及其来源轮次、席位，修订保留前值。主持人可选中下一项并主动启动新一轮。旧模板阶段保留自动完成规则，其他事项由主持人标记。

在单人对话与圆桌之间带入附件时，可以向 POST /api/studio/materials/transfer-check 提交源会话、项目和材料 ID。返回的 revision 用于在确认前核对同一份材料，提交草稿与运行模型分别由用户操作。

附件使用 POST /api/studio/materials 上传，Content-Type 为 multipart/form-data，表单只能包含一个 file，单件最大 12 MiB。请求须带 X-Roundtable: 1；若浏览器发送 Origin，必须与当前 localhost 或 127.0.0.1 服务地址精确同源。成功返回材料的 id、文件名、MIME、大小、文本摘录及可选 read_status。附件保存后不会自动加入任何会议。

创建圆桌时可在 POST /api/studio/sessions 的 JSON 中传可选 material_ids，将最多 12 个已上传附件关联到会话；旧请求省略该字段仍兼容。启动轮次时也可传 material_ids，选择本轮材料并优先提供给席位；每次最多 12 个，成功后材料会关联到会话。完整会话返回 materials 和 board。材料可通过 GET /api/studio/materials/{id} 下载；附 ?preview=1 时，仅 GIF、JPEG、PNG、WebP 会以内嵌图片预览，其它类型仍下载原文件。GET 与 HEAD 为读取接口。

读取会话后，查看 board.state。empty 表示目前只有对话；published 表示可以按 board.modules 的顺序绘制主页。运行期间可用 GET /api/studio/sessions/{id}/board-presence?after={seq} 查看编辑席位、目标字段和临时光标位置。偏移量使用 Unicode 码点。保存的正文和版本以会话快照为准。

修改共享议题板时，向 POST /api/studio/sessions/{id}/board 提交编辑项的 expected_version。例如 {"op":"rename_board","expected_version":1,"title":"候补确认时限"}。成功后返回完整会话；若另一端已修改同一项，409 响应附带最新会话供核对。主持人批注在板上署名 user，下一次公开模型请求会读取当前内容。

桌面圆桌使用 POST /api/studio/materials/{id}/save 保存原件，请发送 X-Roundtable: 1 和 JSON 空对象 {}。用户在系统窗口选择保存位置，成功返回 saved: true，取消返回 saved: false。若返回 browser_download: true，改用 GET 下载。

board.modules 包含议程、材料审阅、观点立场及便笺视图。材料审阅与便笺可带 material_ids 引用本会话附件。AI 对看板的修改提议只有在相应席的公开 say 成功、且本轮成功完成后才会写入；保存的 source_seat 和 source_round 标记公开来源。失败或未确认的轮次不会提交这些提议。旧创建与运行调用无需提供材料字段，继续使用原有行为。

主持人可在项目会议中显式发起 CLI 编辑并在软件中审核变更。主持人的人工保存走独立文件接口和版本检查。规则通过 Magpie 的 Chat system 消息或 Responses instructions 传入，标题命名独立。当前预设尚未经过本项目的讨论质量评测。

文件保存是真实编辑

先读文件，再带回 version 及完整新内容保存。版本是 SHA-256；文件不存在时读取返回 text:"" 与 version:"missing"。新文件须已有父目录；接口不创建目录。

以下路径以 /api/studio/sessions/{id} 开头
方法与路径输入响应
GET …/files无{"files":["README.md",…]}
GET …/file?path=README.md项目内相对路径{"path":"…","text":"…","version":"…"}
POST …/file{"path":"README.md","text":"完整新内容","version":"读取所得版本"}{"path":"…","before":"旧版本","after":"新版本","diff":"…"}
GET …/review同时传查询参数 path、before、after，精确选择已保存修订{"path":"…","diff":"…","added":1,"removed":1}

仅支持允许类型的 UTF-8 文本，每文件至多 2 MiB。隐藏路径、..、绝对文件路径、符号链接、依赖／构建目录、凭据名称及二进制被排除。目录最多包含 10000 个可编辑文件，遍历项最多 50000。目录列表不是完整项目清单。

版本不符返回 409：重新读取并处理差异后再决定保存。服务内写入串行并再次校验；外部编辑器在最终校验与替换之间的极短窗口仍可能发生竞争。网络中断或记录为 unknown 时先看实际文件，勿直接重放。没有删除、执行脚本或构建端点。

审阅具体修订，分别计算增删

GET /api/studio/sessions/{id}/review 查询该会话中主 agent 或用户已记录的实际修改。path、before、after 三项查询参数都必填且只能出现一次，值须与同一条 Change 完全匹配；应分别编码后放入 URL。

GET /api/studio/sessions/{id}/review?path=notes.md&before={change.before}&after={change.after}

返回 path、规范化后的统一差异 diff、新增行数 added 与删除行数 removed。即使同一路径已经改过多次，也按所选修订的 before → after 计算，不累计其他修订，不把当前磁盘内容当作旧版本。接口只查保存记录，不从工作区读取任意文件；仅有写入意图、没有实际修改记录的操作不能用于审阅。

缺少、为空或重复的必需参数返回 400；该会话或完整匹配修订不存在返回 404；历史差异不能规范化返回 422；存档无法读取返回 500。它不会静默改用同路径的最新修改。只有 GET 可用，其他方法返回 405。规范化按请求执行并使用有界缓存，不在会话轮询中重算全部历史。

界面的代码模式显示行级增删；文档模式还可选择字符或字词。后两项由后台 Worker 比较本次修订的连续改变片段计算，不是 API 的 added / removed 字段，也不是全文净字数变化。字符是非空白 Unicode 字素簇；字词按 Intl.Segmenter("zh", {granularity:"word"}) 的 isWordLike 片段计数。TeX、Markdown 等以源码为准，包含语法标记；超过精确比较预算或分词功能不可用时显示无法计算。

模型连接与应用设置

GET /api/studio/models 从当前 Magpie 连接读取 {"models":[{"id":"…","label":"…","source":"…","endpoints":[],"efforts":["auto"]}],"default_model":"…"}。成功时目录可以为空。思考等级由 Magpie 公布；请求选择 auto 时省略推理控制字段。default_model 只有在当前目录里找到已连接模型时才含该模型 ID，否则为 ""。连接或目录读取失败返回 502。

GET /api/studio/magpie-agent 返回 id、installed、enabled、registered、connected、can_install、can_open、restart_required、detail 和可选 model、port。registered 表示 Magpie 能加载 Agent，connected 表示已获得有效连接配置。它们均不执行推理验证。

向同一路径 POST 发送 {"action":"install"} 或 {}，由 Magpie 登记签名应用内置的 Agent。{"action":"open"} 打开 Magpie 桌面应用。注册后在 Magpie 的 Agents 页面刷新、选模型并连接。返回 200 时仍应读取响应里的 registered、connected 与 detail。

POST /api/studio/settings 部分更新设置。桌面协作表单保存 timeout（每次模型请求 10–1800 秒）、max_steps（每位代理 2–40 步）、max_children（每席每轮 0–5 个）。旧设置的 allow_edits 保留为兼容字段。外观 appearance 可为 system、light 或 dark。早期固定席位的型号和 CLI 字段保留给兼容记录与诊断。

模型内部动作仍为 read / write / delegate / say。新圆桌私有子代理继承本席型号和思考档位，只能使用 read / say。父代理最终 say 是公开发言，可附 agenda_updates，并兼容原有收束 followups。子代理结果先交本席主代理，也会随完整会话保存。内部动作由应用协调执行。

插件市场与会中动作

GET /api/studio/plugins 返回 {"sources":[],"available":[],"installed":[]}。POST 同一路径按 action 管理插件来源和安装状态；成功均返回更新后的 View。

action字段用途
subscribeurl订阅插件来源。
refresh / unsubscribesource_id刷新或取消订阅来源。
installsource_id、id、sha256、grants；可选 version安装所选来源中的插件并明确授予权限；若提交 version，当前目录必须有完全匹配版本。
enable / disable / uninstallid、source_id、version、sha256启用、停用或卸载已安装插件；四项须与当前安装记录匹配，否则拒绝变更。

installed 中每项包含 source_name 和 sha256。启用、停用或卸载前，应将当前安装项的 id、source_id、version、sha256 原样传回，只有与当前安装匹配时才会执行状态变更。

grants 可选权限为 round.guidance、report.guidance、code.execute、meeting.public_turns、meeting.report。仅获授权的能力和会议材料可提供给插件。

POST /api/studio/sessions/{id}/plugin-action 需要 plugin_id、action_id、version、source_id、sha256。可选 from_round、to_round 只限制 meeting.public_turns 的公开发言范围；不用于其他权限数据。响应为 {"format":"markdown|text","text":"…","filename":"…","native_save":true}；native_save 指示客户端可否使用系统保存窗口。

将插件输出提交到 POST /api/studio/plugins/save-output：{"filename":"建议文件名.md","text":"…","format":"markdown"}。filename 只是建议名称，不是路径；路径仅由用户在系统保存对话框中选择。已保存返回 {"saved":true}，用户取消返回 {"saved":false}。没有可用桌面保存窗口时返回 {"browser_download":true}，客户端改用标准浏览器下载。

会话轮次和报告分别保存适用阶段的 plugin_guidance 快照，每项含 id、name、version，以及该阶段的指导正文。历史快照保留当时的版本和正文；启停或更新插件不改写已经保存的轮次与报告。

本机 CLI 安装与版本

桌面设置调用 GET /api/studio/cli-health，只返回确认已安装的入口，clients 中每项可含 version。state 为 ready、check_failed 或 unverified。该接口执行限时的版本命令，检查独立入口能否启动。登录、模型能力和额度不属于此检查。

兼容接口 GET /api/studio/clients 重新读取本机可执行文件与安装信息，返回 {"clients":[…],"checked_at":"UTC 时间"}。检查范围包括 Codex、Cursor Agent、Claude Code、Gemini CLI、GitHub Copilot CLI、OpenCode、Qwen Code、Aider、Kimi CLI、Pi、Amp 和 Droid。没有 POST、安装或登录操作。

clients 数组的每项字段
字段含义
id / name稳定标识／客户端显示名称。
installed / stateinstalled 是布尔值，只有 state:"installed" 时为 true。not_found 表示当前搜索范围没有找到；unverified 表示找到同名程序但无法确认对应客户端。
command / path首选命令名／发现的可执行入口路径；未找到时省略路径。unverified 可包含尚未核实的候选路径。

探测使用已保存的 Codex／Cursor 自定义路径、继承的 PATH、常见安装目录及有限的版本管理器目录；不递归扫描整个用户目录。它只检查文件、安装位置及必要的少量包元数据／启动脚本，不运行 CLI、Shell、安装器或登录命令，不读取账户文件、不访问网络，也不发送模型请求。

旧连接诊断

此接口保留早期 Codex、Cursor 与 Magpie 路径的诊断。当前桌面设置分别读取模型目录、Agent 状态和独立 CLI 版本。

GET /api/studio/diagnostics 只返回本次服务运行期间保留的结果，不启动命令、不访问网关，也不调用模型。服务重启后各来源为 unchecked；改变端口、主模型、CLI 路径或 Codex 接入方式后，相关旧结果会标记为待重检。

POST /api/studio/diagnostics 主动预检。传 {} 检查全部来源，也可用 target 选择 all、magpie、codex 或 cursor。Codex 使用 Magpie 路径时，检测 Codex 也会检测网关；其他未选来源沿用缓存，并保留各自的 checked_at。

POST 可选字段；单个 JSON 对象至多 64 KiB，不接受未知字段
字段作用与约束
target检测目标，省略或空串等同 all。
magpie_port / codex_transport仅本次检测覆盖网关端口（1–65535）／Codex 路径（magpie 或 direct）。
models / cli_paths按 codex、cursor 键覆盖主模型／程序路径。模型至多 160 字节且无空白或 NUL；CLI 路径为空时自动发现，否则须为官方程序名的绝对路径，至多 4096 字节。

任一覆盖字段提供非 null 值（包括空对象映射）时返回 preview:true，不保存设置；覆盖字段传 null 视为未覆盖。未提供的项沿用已保存设置。预检结果会进入内存缓存，之后 GET 仍会对照已保存设置标记不匹配来源；preview 记录上次请求是否为预检。

  "target": "codex",

响应始终包含 checked_at、preview 与 sources，后者包含 magpie、codex、cursor。每个来源包含 state、title、detail；状态为 unchecked、ready、warning 或 error。尚未检测时顶层时间为空串；来源时间仅在已有检测记录时出现。

根据检测结果还可返回 version、transport、model、login_state、auth_method；网关可返回 port、models_count、models 与 model_available。models_count 是有效网关目录 ID 的去重总数（含其他来源和路由分组）；models 只列可作为 Codex 候选的 codex/… ID，两者数量可以不同；数量为零或候选为空时对应字段省略。

网关在线但所选模型缺失时，Magpie 为 warning、model_available:false；使用该网关路径的 Codex 为 error。这与网关无法连接不同。login_state 为 unknown / logged_in / not_logged_in；auth_method 为 chatgpt / account / api_key，未核实时省略。API 不返回密钥、登录令牌或厂商原始命令输出。

预检只读取本机 Magpie 的身份和模型目录，以及官方 CLI 的版本与登录状态；不会执行登录、退出账户或发送推理请求。ready 仅表示对应预检通过，不证明实时额度、推理、所选 CLI 模型或工具兼容性。检测有 18 秒总期限，单条 CLI 状态命令最多 5 秒；连接失败或超时通常记录在 200 响应的来源状态中。

已有检测运行时返回 409；参数错误或超过 64 KiB 返回 400；请求取消且仍可响应时返回 408，并保留上次结果。请先查看各来源的 detail 再决定后续操作，检测不会自动切换请求路径。

输入无效或请求过长；修正后提交。Studio 超限通常为 400。
403

422
